## What it does

| Feature | What you get |
| --- | --- |
| [Peer to peer](/docs/how-it-works#sending-a-message) | Messages go straight from device to device, directly or through a relay. qop runs no message servers |
| [Handles](/docs/app#create-your-qop) | No phone number or email. You pick a permanent handle, and people find you by it |
| [Keys on device](/docs/how-it-works#accounts-and-devices) | Each device makes its own key pair. The private half never leaves it |
| [Verified peers](/docs/how-it-works#the-registry) | A public registry maps handles to device keys, and both sides check it before a message is accepted |
| [Linked devices](/docs/devices#link-a-device) | Up to four, each approved from your phone and removable later |
| [Recovery key](/docs/devices#your-recovery-key) | Your owner key, exported. It controls the device list, separately from sending |
| [Terminal](/docs/cli) | The CLI chats as you, and holds messages for your phone while it's away |
| [Open source](https://github.com/deepso7/qop) | Every part is on GitHub, built on [minip2p](https://minip2p.com), and you can run your own |

## Chat from a terminal

The CLI is a second device on your account. Link it with `qop link`, approve it on your phone under **Profile → Devices**, then `qop start` sends and receives as you:

```sh
qop link --account you
qop start --to alice --message "hello from the terminal"
```

Messages are saved before they're acknowledged, and anything sent while alice is offline stays queued until she's back. See [CLI](/docs/cli) for setup.
