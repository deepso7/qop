The app is an Expo project in `mobile/`. It needs a development build: Expo Go can't load minip2p's native module.

## Configure

Copy `mobile/.env.example` to `mobile/.env` and set:

| Variable | Description |
| --- | --- |
| `EXPO_PUBLIC_API_URL` | Your qop API. |
| `EXPO_PUBLIC_RPC_URL` | RPC endpoint the app uses to read the registry. |
| `EXPO_PUBLIC_REGISTRY_ADDRESS` | Deployed registry address. |
| `EXPO_PUBLIC_REGISTRY_CHAIN_ID` | Chain ID of the registry. |
| `EXPO_PUBLIC_RELAY_ADDRS` | Comma-separated minip2p relay multiaddresses. |

The registry address and chain ID also pin the EIP-712 domain your owner key will sign for.

Phones and emulators need addresses that can reach your development machine, so `127.0.0.1` usually doesn't work. Use your machine's LAN address, or on Android forward the ports with `adb reverse`.

## Run

From the repository root:

```sh
pnpm --filter mobile ios
pnpm --filter mobile android
```

Each command builds a native development client and connects it to Metro. After changing native dependencies, regenerate the native projects and reinstall iOS pods before reusing an existing Xcode workspace.

## Switching registries

Registrations are stored per chain and registry address. Pointing the app at a different registry means registering again, but your identity keys and conversations stay on the device.
