A qop network is three things you deploy, plus the minip2p relay. Every client must point at the same registry and chain.

| Piece | Source | What you run |
| --- | --- | --- |
| [Identity registry](/docs/self-hosting/registry) | `contracts/` | A Solidity contract on a Cancun-compatible EVM chain |
| [API](/docs/self-hosting/api) | `api/` | A Node service with a Postgres database |
| [App](/docs/self-hosting/app) | `mobile/` | An Expo build configured for your registry and API |

The [CLI](/docs/cli) uses the same settings as the app. Neither has a built-in relay: the example env files set a public minip2p relay in `EXPO_PUBLIC_RELAY_ADDRS` and `QOP_RELAY_ADDRS`. Keep those values or replace them with your own relays.

## Prerequisites

- Node.js at the version pinned in the root `package.json` (currently 24.22.1). pnpm enforces it.
- pnpm
- [Foundry](https://getfoundry.sh) for the contract
- Postgres for the API
- Xcode or Android Studio for a mobile development build

## Get the code

```sh
git clone https://github.com/deepso7/qop
cd qop
git submodule update --init --recursive
pnpm install
```

Then follow the pages in order: deploy the registry, run the API, and build the app.

## Checks

```sh
pnpm check            # lint, package tests, and typecheck
pnpm check:contracts  # forge fmt, lint, and tests
```

The automated tests don't exercise the native peer-to-peer transport, which needs two development builds. `mobile/README.md` has a manual checklist for that.
